# 备份、恢复和迁移

建议至少 3 份数据、2 种介质、1 份异地副本。同一物理磁盘里的另一个文件夹不能防止整盘损坏。

## 备份

设置中的“立即备份”将原图、sidecar、信件、归档配置和 SQLite 一致性快照写入 `/backups` 的临时目录。数据库使用 SQLite Online Backup API；备份清单记录文件路径、大小和 SHA-256，校验成功才完成备份。缓存、缩略图和衍生导出无需作为唯一保存副本。

`/backups` 必须与 `/data` 分离，后端拒绝源目录内部的备份目标。失败或取消不能覆盖之前的成功备份。

## 恢复演练

1. 设置 → 刷新备份列表，选择一个完成的备份。
2. 输入一个新的目标名称，确认恢复。
3. 程序先验证清单，再恢复至 `/backups/restored/<name>`；目标必须为空，不自动合并当前归档。
4. 查看成功摘要并核对原图、日期、日记和照片哈希。
5. 切换归档需停止应用，将新路径挂载为 `/data`，再启动。保留原归档，验证前不删除。

Windows 桌面版的恢复副本同样先写入当前备份目录下的 `restored/<name>`。由于归档与备份必须独立，不能直接在桌面设置中选择这个嵌套目录。关闭应用后，将完整恢复副本复制到备份目录之外的新空目录，再通过桌面设置选择复制后的目录、保存并重启。详细步骤见 [Windows 迁移说明](WINDOWS_MIGRATION.md)。

## 跨电脑迁移

停止容器，把完整归档目录复制到新电脑，通过 `compose.bind.yaml` 将其挂载为 `/data`。所有照片路径相对根目录；应用会从 JSON 建立索引。不要只复制 SQLite。未来信件和归档设置也应一起复制。

默认命名卷可用临时容器复制到宿主机：先停止 Dayframe，再使用 `docker cp` 从仍存在的容器复制 `/data/.`（`docker compose stop` 保留容器）。也可在 Docker Desktop Volumes 中导出卷。备份卷应单独导出。

## 故障处理

- SQLite 丢失/损坏：保留归档副本，重新启动或执行索引重建；不要删除原图和 sidecar。
- 原图丢失：完整性检查给出报告；从校验通过的备份恢复，元数据不会因缺图自动删除。
- 哈希变化：不要覆盖备份；先保存故障副本再核对原件。
- sidecar 损坏：先备份文件，健康检查后根据恢复文件或旧备份处理；不通过猜测重建日记。
- 文件权限不足：修正宿主机挂载目录的 UID/GID 写权限，不要改用应用安装目录保存唯一照片。

没有独立备份时，唯一硬盘损坏无法由软件补救。
