# Dayframe v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Track checks below and do not pause for approval: user explicitly requested uninterrupted execution.

**Goal:** A real local personal selfie archive delivered as a Docker application in pppel-lg/DayFrame.
**Architecture:** React/Vite frontend and FastAPI backend serving one origin. Durable archive files, rebuildable SQLite index, independent backup mount. Browser camera permission stays explicit.
**Tech Stack:** Python 3.12, FastAPI, Pillow, SQLite, React, TypeScript, Vite, Docker.
**Spec:** Dayframe.md and docs/superpowers/specs/2026-10-27-dayframe-design.md.

## Global Constraints
- Original bytes immutable; JSON sidecars authoritative; paths relative; format_version=1.
- UI default Simplified Chinese; offline core; no account or external photo service.
- Backups outside archive; full SHA256 validation; restore to empty destination only.
- User authorizes development, packaging and GitHub publication without further questions.

## Review Focus
- Malformed metadata/path traversal/symlinks must never escape the authorized archive.
- Missing original must not erase diary or count as a completed day.
- Interrupted save and database corruption must preserve prior metadata and be recoverable.
- Date denominators, leap day, timezone and archive-start bounds must be consistent.
- Pairing expiry and mobile-only credentials must not grant private archive access.
